# Roadmap — поэтапный план

Каждая фаза самостоятельно тестируема и заканчивается приёмочной проверкой на железе. Отслеживается в таск-листе сессии (Phase 0…6).

---

## Phase 0 — host bring-up по USB-CDC (без изменений прошивки)

**Цель:** доказать командную поверхность раньше любого протокола/прошивочной работы.

- Rust-скелет ядра: `UsbTransport` + сырой проброс к существующему CLI (legacy-режим): шлём `wifi scan`, читаем до `# `.
- Минимальный CLI-раннер на Python поверх pyo3 для ручной проверки.

**Acceptance (HW):** устройство перечисляется как USB-CDC; команды выполняются; вывод считывается; виден `# `-промпт. Никаких правок прошивки.

---

## Phase 1 — фрейминг в прошивке (по USB)

**Цель:** ввести кадровый протокол и неблокирующий путь.

- Прошивка: `src/core/companion/companion.{h,cpp}` + `FramingSerialDevice` + `HELLO`/auth + ветка без `backToMenu()`; всё за `companionEnabled` (дефолт off).
- Хост: кодек протокола (`REQ/RSP/END/ERR`) + рукопожатие по USB.

**Acceptance (HW):**
- `HELLO` возвращает корректные fw/board/`caps`;
- `wifi scan` проходит round-trip с чистым `END`;
- **при включённом companion-режиме выполнение хост-команды НЕ выкидывает устройство из текущего экрана** (главный приёмочный тест неблокирующести);
- при `companionEnabled=false` поведение = текущее (регресс-проверка).

---

## Phase 2 — тот же протокол по BLE

**Цель:** перенести протокол на BLE без изменений в самом протоколе.

- Хост: `BleTransport` (btleplug): поиск `Bruc`/сервис `4371ec0b-…`, подписка на нотификации `d555ed97-…`, один кадр на один write, MTU exchange.

**Acceptance (HW, в т.ч. uConsole):**
- discovery + `HELLO` + `wifi scan` по BLE;
- замер реальной частоты нотификаций (подтвердить потолок из-за 10мс-задержки);
- автономный UI устройства продолжает работать при активном подключении;
- **проверить BLE именно на uConsole** (CM4 ок; CM5 — отдельно, возможны патчи ядра).

---

## Phase 3 — события, стриминг, передача файлов

**Цель:** снять лимит BLE через «захват→выгрузка» и дать асинхронные события.

- Прошивка: эмиссия `EVT`; `companion stream start/stop`; busy-флаг → `BUSY`; chunked-base64 `companion file get/put` + sha256.
- Хост: шина событий, подписка на стрим, сборка/сверка файлов.

**Acceptance (HW):**
- старт/стоп потока захвата (beacon/sub-GHz);
- передача `.sub`/`.cap` в обе стороны с проверкой целостности;
- при активной модальной радио-фиче companion-команда к занятому ресурсу возвращает `BUSY` (не падение).

---

## Phase 4 — полный TUI

**Цель:** рабочий интерактивный TUI поверх ядра.

- Python/Textual: менеджер подключений (BLE+USB), capability-driven меню, таблицы сканов, live event-log, файловый браузер/трансфер, raw-command консоль.

**Acceptance (HW):** полная сессия на uConsole по BLE; обработка переподключений; корректная деградация при отсутствующем `cap`.

---

## Phase 5 — GUI + host-compute augmentation

**Цель:** GUI с паритетом функций + перенос тяжёлой обработки на хост.

- Python/PySide6 поверх того же ядра: дашборд, визуализации сканов, потоковый вид (high-rate — только USB), файловый менеджер.
- `companion_compute`: разбор/анализ выгруженных захватов (WiFi handshake → hashcat/aircrack; sub-GHz/NRF декодеры; БД захватов; визуализация). См. [`host.md`](host.md#host-compute-augmentation).
- Артефакты упаковки под aarch64 (uConsole) и x86_64.

**Acceptance (HW):** паритет с TUI; хотя бы один полный host-compute пайплайн (например, WiFi handshake → словарная атака на хосте); собранные артефакты под обе арки.

---

## Phase 6 — пропускная способность + безопасность

**Цель:** убрать искусственный потолок и закрыть BLE.

- Прошивка: заменить blanket `vTaskDelay(10ms)` после `notify` на credit/ack-flow; поднять MTU/DLE; NimBLE bonding + per-session токен (см. [`security.md`](security.md)).
- (Заодно) починить баг `vprintf` (`BLESerialService.cpp:62`).

**Acceptance (HW):** измеренный рост пропускной способности; рабочий pairing-флоу; нет регресса автономного использования.

---

## Реестр рисков

| Риск | Влияние | Митигация |
|---|---|---|
| Гонки за общую SPI/I2C шину (CC1101/SD/дисплей/NRF) | зависания/порча данных | один serial-таск + общие блокировки шины; busy-арбитраж (`firmware.md` §3-4) |
| `backToMenu()` ломает UI | потеря автономности | companion-путь без `backToMenu()` (главное изменение) |
| BLE на uConsole CM5 | нет связи | ранняя проверка в Phase 2; fallback на USB |
| Потолок BLE ~2–24 КБ/с | нет live по BLE | модель «захват→выгрузка»; live только по USB; Phase 6 flow-control |
| Интерпретатор убивает serial-таск | пропадание компаньона | задокументировано; координация — later |
| Баг `vprintf` (128B/va_list) | порча framed-вывода | не использовать printf-путь; починить в Phase 6 |
| Упаковка PySide6 под aarch64 | сложная дистрибуция | проверить wheel/AppImage в Phase 5; TUI как минимально-зависимый fallback |
| Открытый BLE без авторизации | удалённое управление радио | токен в `HELLO` с Phase 1; bonding в Phase 6 (`security.md`) |
